# MCP2UNITY

**Version: 0.5.2 (experimental backport)** | **Unity: 2022.3 LTS (validated on 2022.3.62f3)** | **Windows PowerShell companion**

MCP2UNITY restarts the original Wasim Unity MCP Bridge from its **v0.5.1** source instead of upgrading the transport to v0.6.0. The v0.5.1 standalone PowerShell companion and its Unity Editor file-IPC architecture are retained; 17 optional tools from v0.6.0 are backported into separate Editor modules. This rebuild has 21 original tool entries + 17 backported entries + 1 reviewed Transform tool + 8 uGUI tools = **47 advertised MCP tools**.

> **Verification status:** All **73/73 EditMode tests (Phases 1–3)** passed in Unity 2022.3.62f3 with the connected MCP bridge advertising 47 tools and no reported compilation/Console errors. Canvas/Panel/Button/Styling/Layout creation was exercised end-to-end in the MuOnBaAr test scene, which was restored to five original root objects. **Phase 4 PlayMode interactions passed 13/13**, bringing the measured total to **108/108 Unity tests** (95 EditMode + 13 PlayMode) on 2026-11-10, including 10/10 Phase 5 UI serialization and persistence tests. Direct live MCP-created UI Hide/Show interaction was also verified in Game View (target `activeSelf` changed false/true) and the temporary Canvas/EventSystem were removed; the original five scene roots were verified. Unity compilation and Console were clean after UPM update. No standalone Windows companion/player-build certification is implied.

## Why this build?

- Keep the v0.5.1 companion process, ngrok lifecycle, script-inspection tools, and existing script-change approval workflow.
- Isolate v0.6.0 runtime inspection, rollback, scene/view diagnostics, profiler and Editor/Test Framework actions behind modular handlers.
- Add only narrow communication patches for MCP image envelopes, JSON array preservation, request expiry, and no replay of interrupted operations.
- Require local review for scene/script change sets and Editor actions. Neither can be approved remotely.

## Install from GitHub (UPM)

1. Back up the project. Remove the old `com.wasimdevelopment.unity-mcp-bridge` package if it is installed; both packages retain the same Editor assembly name and must **not** be installed together.
2. In Unity 2022.3, open **Window > Package Manager > + > Add package from git URL**.
3. Enter:

   ```text
   https://github.com/MusafirEx/MCP2UNITY.git
   ```

4. Allow Newtonsoft JSON 3.2.1 and Unity Test Framework 1.1.33 dependencies to resolve. Check the Console for compile errors before starting anything.
5. Open **Window > Wasim Development > Unity MCP Bridge**, configure the Windows PowerShell executable and ngrok. Close any companion from an earlier installation before starting this one.
6. Click **Start Companion** and run **Local MCP Self-Test**. It should advertise 47 tools and complete a `unity_get_status` round trip. Use the private MCP endpoint generated by the bridge, not an unauthenticated public URL.

This URL installs from the repository's default branch, **`main`**. To explicitly select it, append `#main` to the URL. To keep a reproducible package version, pin a specific commit using `#<commit-sha>` instead. Unity Package Manager resolves Git revisions when the package is installed or updated; it does not automatically fetch every new commit. The former `#rebuild/v051-backports` install link is no longer recommended.

The tool catalog is visible only when the companion and Unity IPC are running. If requests fail during compilation, wait until Unity finishes importing before trying them again. A request that times out or is interrupted is intentionally not replayed.

### Change sets and Editor actions

The `unity_set_transform` tool prepares local/world Position, Euler Rotation and Scale changes (absolute or relative) as **reviewed change sets**. It does not modify the scene until approved locally. World scale on nonuniformly scaled parents is rejected; [details and examples](Documentation~/TOOLS_V060.md#transform-tool-mcp2unity-extension).

Enable the specific permissions in the bridge window, then review local proposals through **Window > Wasim Development > Change Sets and Actions**. Approval and rollback are local actions, not public MCP endpoints. Review every proposed operation; Unity callbacks and project tests may execute project-defined code.

### Unity uGUI Phases 1–4

The following eight uGUI MCP tools are included in the catalog:

- `unity_create_canvas` — queue creation of a Canvas, CanvasScaler, GraphicRaycaster and optional EventSystem.
- `unity_create_ui` — queue Panel, Image, Button, legacy Text, TextMeshProUGUI, Slider, Toggle, InputField or ScrollView creation under an existing Canvas; each element uses RectTransform.
- `unity_set_rect_transform` — queue Anchor Min/Max, Pivot, Size Delta or Anchored Position edits.
- `unity_inspect_ui` — read a bounded uGUI hierarchy, including RectTransform, text, colors, button interactability and LayoutGroup details.
- `unity_set_ui_property` — submit reviewed edits of text, font size, graphic color, interactable, raycastTarget, Image fill and sprite asset reference.
- `unity_set_ui_layout` — submit reviewed Horizontal/Vertical/Grid LayoutGroup configuration including spacing, padding, cell size and column/row constraints.
- `unity_bind_button_event` — only binds a persistent Button.onClick → GameObject.SetActive(bool) targeting a UI object under the same Canvas; arbitrary event targets/methods are rejected.
- `unity_delete_gameobject` — propose deletion of a saved scene GameObject with exact-name confirmation, a maximum subtree size (≤100), Unity Undo, local approval, and scene-file backup. Prefab instances/assets are protected.

Write tools only propose locally reviewed changes, so the Unity Review window must approve them. No remote approval endpoint is added. Creation operations support aliases (including `$createdCanvas` and `$createdUi` for dedicated calls) and retain scene-backup rollback.

See [Unity uGUI MCP tools](Documentation~/UNITY_UI_TOOLS.md) for schemas and test scope. UI Toolkit/UXML, arbitrary runtime callback method bindings, and advanced Button events beyond allowlisted SetActive(bool) are **not supported**. All 73 Phase 1–3 EditMode tests passed in Unity 2022.3.62f3, and the direct Canvas/Panel/Button/Styling/Layout MCP integration test succeeded. Phase 4 adds 13 separate PlayMode tests of actual UI event dispatch and input behavior. All **13/13 PlayMode tests passed** through the reviewed Unity Test Runner action on 2026-11-10; PlayMode fixture tests do not by themselves demonstrate serialized MCP event persistence or clicks in every target game scene. The rollback guard correctly blocked an unsafe restore when scene files diverged; temporary UI was removed manually, and the original five root objects were verified.

## Architecture

```text
MCP Client -> ngrok HTTPS -> PowerShell companion (v0.5.1 base)
                                      |
                              Library/ file IPC
                                      |
                              Unity Editor dispatcher
                               |              |
                         21 legacy tools   17 modular tools
```

- No model API key is embedded.
- Editor-only assembly; no runtime/player build bridge.
- Paths and user-approved changes are restricted to the permitted project locations.
- Keep private capability URLs and ngrok tokens out of public Git commits and issue logs.
